# Use cases, audience and post-op review

- **Topic:** Master plan ch. 1.1: who the MVP is for and how review works
- **Choices (Karthi, 24 Sep 2026):**

| Question | Options considered | Choice |
|---|---|---|
| Main use case | New surgery main · both equal · archive main | **Both equal**: 🆕 new surgery (live) + 🗄 archive (batch) |
| Surgeon time after surgery | ~1 min · 2–3 min · 5–10 min · unknown | **2–3 min** |
| Demo audience | A CEO · B surgeons/hospital · C investors | **A + B + C** |
| Clinician for small checks | none · a few hours · maybe later | **None** → guideline-grounded, labelled 🧪 synthetic |
| Archive reviewer's cards | separate label · need surgeon later · count the same | **Separate trust label**: ✅ surgeon-approved vs 👁 reviewer-checked |
| Debrief device | phone · tablet · PC | **Web app first** (desktop), debrief screen works well on a phone browser; phone app later |
| How "why" is answered | voice + tap · voice · tap · typing | **Voice + tap** |
| Dataset license status | — | **Unknown to the team** → checked: CC BY-NC-SA 4.0 (non-commercial) → CEO ask |

- **Reason:** New surgeries need the operating surgeon's input while memory is fresh, in the few minutes before the next case. Processing after the end takes ≈ 15–45 min, so processing must run live and drafts must be ready ≈ 3–5 min after the end. Archive videos have no time pressure but no operating surgeon either, so their cards carry a different trust label.
- **Claude's caution:** three audiences + two equal use cases is a lot for two people. Mitigation: one pipeline serves both use cases; investor polish goes last.
- **Decided by:** Karthi · 24 Sep 2026
